# 夜班接驳车末班核定与线路时刻质检

给夜班通勤协调员用的 Web 工具，包含两个功能页：

1. **末班核定**：输入时刻表首页 URL、上车站、下车站、最早出门与到岗截止的
   日期时间，自动翻页抓取两站时刻表，按**车次号 + 停站顺序**配对，只保留
   “发车不早于出门、到站不晚于截止”的班次，给出**发车最晚的一班**及两站来源。
2. **线路时刻质检**：输入时刻表首页 URL、车次号、按行驶顺序排列的站名和
   各站间最长分钟数，逐站抓取分页，按**服务日类型与停站顺序**对齐整条线路，
   连续换算 `00:xx` / `24:xx` 混写的跨午夜时刻，列出**站间超时、缺站、
   站序冲突**的站段及来源；同站同服务日无法唯一对应的记录标为**待核实**。
   某站分页失败时，只把依赖该站的结果标为待核实，其余已确认异常照常显示，
   且不会断言全线正常。

## 功能要点

- **分页抓取**：从首页的站点链接（`a.station-link`）找到两站第 1 页，沿
  `a.next-page` 逐页抓取，直到没有下一页（50 页上限、循环链接保护）。
- **配对规则**：两站记录车次号相同，且上车站停站顺序早于下车站才视为同一行程。
- **服务日区分**：按车次**始发服务日**标注工作日（周一至周五）/ 周末（周六周日）/
  每日；查询时按时间窗覆盖的每个始发日分别判断是否运行。
- **24:xx 跨日时刻**：`24:25`、`25:10` 等按“始发服务日零点 + 时间差”换算为真实
  日期时间；若下车站时刻（如 `01:00`）早于上车站发车（如 `23:50`）且未用 24 小时
  制书写，自动按次日处理。
- **异常提示**：
  - 任一分页抓取失败 / 表头缺列 / 链接循环 → 提示“无法核定末班”，且不展示不可信结论；
  - 车次缺停站顺序、缺关键时刻、两站服务日标注不一致、下车站无该车次记录 →
    逐条告警；若仍有其他完整班次，正常给出末班，告警与答案同时展示。
- 结果页展示末班车次、服务日类型、两站实际到发时间与原始时刻、两站来源 URL，
  以及时间窗内全部可选班次。

- 示例时刻网站：<http://localhost:5001/>
- 末班核定应用：<http://localhost:8000/>（顶部导航可切换到「线路时刻质检」）

### 线路时刻质检怎么填

打开 <http://localhost:8000/qc>（容器内抓取 URL 必须填容器网络可达的服务名）：

| 字段 | 示例值 |
| --- | --- |
| 时刻表首页 URL | `http://example-site:5001/` |
| 车次号 | `N302` |
| 站名（按行驶顺序，每行一个） | `滨河园区` → `东门枢纽` → `中央厂区` → `夜班宿舍` |
| 站间最长分钟数（每行一个，与站段一一对应） | `30`、`50`、`50` |

提交后页面给出：

- **问题清单**：每条注明状态（已确认异常 / 待核实）、类型、服务日类型、
  站段或站点、说明与来源分页 URL；
- **各站分页抓取状态**：分页完整或抓取失败（含失败原因）；
- **连续换算时刻轴**：`23:40 / 24:05 / 00:45 / 01:20` 等混写时刻统一换算为
  “当日/次日 HH:MM”，并保留原始时刻；
- **站间耗时核算**：逐站段对比实际耗时与最长允许分钟数。

### 质检演示车次（示例站内置）

| 车次 | 演示点 |
| --- | --- |
| `N301` | `00:xx` 与 `24:xx` 混写、全线正常（唯一显示“全线质检通过”的车次） |
| `N302` | 中央厂区→夜班宿舍实际 70 分钟，超过 50 分钟上限（已确认·站间超时） |
| `N303` | 缺少中央厂区停站记录（已确认·缺站），周末班次 |
| `N304` | 东门枢纽停站顺序被错标为 3（已确认·站序冲突） |
| `N305` | 中央厂区同站同服务日两条记录（待核实，无法唯一对应） |
| `X901` | 故障北站第 2 页 HTTP 500：依赖该站的站段待核实，页面不能断言全线正常 |

### 质检规则要点

- **服务日对齐**：按工作日 / 周末 / 每日分别建立时刻轴；同一车次各站服务日
  标注不一致时，在对应轴上表现为显式缺站，不会被静默合并。
- **连续换算**：时刻一律按“始发服务日零点 + 时长”解析（支持到 `47:59`）；
  后站时刻不晚于前站时自动按次日回卷一次，仍回卷不上则记时刻顺序矛盾。
- **失败隔离**：某站分页抓取失败只影响与该站相邻的站段（待核实），
  其他站段已确认的超时/冲突结论照常保留；存在失败站时永远不显示全线正常。

### 末班核定页怎么填

在 <http://localhost:8000/> 页面填写：

| 字段 | 示例值 |
| --- | --- |
| 时刻表首页 URL | `http://example-site:5001/`（容器间用服务名访问） |
| 上车站 | `滨河园区` |
| 下车站 | `中央厂区` |
| 最早出门 | `2026-11-11 22:00` |

## 本地直接运行（不用 Docker）

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r app/requirements.txt

# 终端 1：示例时刻网站
cd example-site && python app.py            # http://localhost:5001

# 终端 2：核定 + 质检应用
cd app && flask --app commuter.app run      # http://localhost:5000
```

此时首页 URL 填 `http://127.0.0.1:5001/`（或 `http://localhost:5001/`），
质检页地址为 <http://localhost:5000/qc>。

## 试一下异常场景（末班核定）

- **缺记录**：示例数据里 N206 在「中央厂区」没有停站记录，任意
  滨河园区→中央厂区查询都会看到黄色数据告警，末班仍由 N205 等完整数据核定。
- **分页失败**：上车站填「故障北站」，其第 2 页返回 HTTP 500，页面显示红色
  “无法核定末班”，并标明失败的分页地址。
- **周末 vs 工作日**：把时间窗放到周六晚上（如 2026-11-14 22:00 至
  2026-11-15 02:00），结果中只会出现“每日”和“周末”班次。

## 适配真实时刻表站点

抓取器对页面结构的约定（见 `app/commuter/scraper.py`）：

1. 首页上站点链接带 `class="station-link"`，文本为站点名；
2. 站点页有 `<table>`，表头包含 车次号 / 停站顺序 / 站点 / 时刻 / 服务日
   （支持常见别名，如“站序”“班车”“到时”等，见 `_HEADER_ALIASES`）；
3. 翻页链接带 `class="next-page"`；
4. 服务日列出现“工作日/平日/weekday”“周末/双休/weekend”“每日/daily”等字样。

结构不同的站点只需调整 `scraper.py` 中的选择器与表头别名，核心核定逻辑
（`times.py`）无需改动。
